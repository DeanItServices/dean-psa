<objective>
Set up Docker Compose (Next.js app + PostgreSQL), initialize Prisma, and define the base data model (User, Role enum, Session, Account) that Plan 01-03's auth/RBAC layer depends on.

Purpose: This plan provides the persistence layer and containerized runtime every later phase's data model builds on top of. It is independently verifiable from Plan 01-01's frontend scaffolding.
Output: A working `docker compose up` bringing up the app + database, with Prisma migrations applied against a User/Role/Session/Account schema.
</objective>

**Execution environment**: This project runs on Windows with Git Bash as the shell of record (the Bash tool in this environment invokes Git Bash). All verification commands in this plan are POSIX shell syntax (`test -f`, `grep -q`) and MUST be run through Git Bash, not PowerShell or cmd.exe.

**Dependency naming note**: This plan installs the pure-JavaScript `bcryptjs` package specifically (NOT the native `bcrypt` package, which requires compiled bindings that can fail in Alpine-based Docker images without build tools). Every reference to password hashing in this plan and in Plan 01-03 means `bcryptjs`'s `hash`/`compare` functions, imported as `import { hash, compare } from "bcryptjs"`.

Relevant decisions from 01-CONTEXT.md:
- ORM/migrations: Prisma against PostgreSQL
- RBAC model: `Role` enum column on `User` (technician | dispatcher | sales | finance | admin) -- NOT a full Permission/RolePermission database schema
- Auth: Auth.js (NextAuth v5) with Credentials provider + Prisma adapter, bcrypt password hashing, database sessions (requires Session and Account models matching the Auth.js Prisma adapter contract)
- Deployment: Docker Compose running both the Next.js app AND Postgres
