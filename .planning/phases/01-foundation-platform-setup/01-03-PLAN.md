Output: Working email/password login backed by database sessions, with role-based authorization enforced in middleware.

**Known Auth.js v5 constraint -- database sessions cannot be validated in Next.js Edge middleware.** `PrismaAdapter` requires a Node.js database connection, but Next.js middleware runs in the Edge runtime by default, which cannot execute Prisma queries. Using the full `auth()` instance (the one configured with `PrismaAdapter` and `session: { strategy: "database" }`) directly inside `src/middleware.ts` will fail at runtime even though it may typecheck. This plan resolves it using Auth.js's own documented split-config pattern:
- `src/auth.config.ts` -- an Edge-safe, adapter-free config containing ONLY the `pages` option (custom login page path) and an `authorized` callback that checks for the presence of a valid session cookie/token. No `PrismaAdapter`, no `Credentials` provider (Credentials providers with a database lookup are also not Edge-safe). This is the config `src/middleware.ts` imports.
- `src/auth.ts` -- the full config (imports and spreads `authConfig` from `auth.config.ts`, then adds `PrismaAdapter(db)`, the `Credentials` provider, and `session: { strategy: "database" }`). This is the config used everywhere else: API route handler, Server Components, Server Actions (via `getCurrentUser()`/`requireRole()` in `src/lib/session.ts`).
- `src/middleware.ts` calls `NextAuth(authConfig).auth` (the lightweight Edge-safe instance) purely to redirect unauthenticated requests to `/login` at the edge for UX speed. It does NOT perform role-based authorization -- role checks happen server-side in `src/lib/session.ts`'s `requireRole()`, called from the Plan 01-04 dashboard layout (already planned as defense-in-depth there). This means middleware answers "is there a session cookie at all" (fast, Edge-safe, coarse) while server components answer "does this user have the right role" (authoritative, Node runtime, fine-grained). Document this split explicitly in this plan's SUMMARY.md so Plan 01-04 and future phases understand middleware is not the authorization boundary for roles.
