Required interfaces/content structure:
- `enum BillingType { block_hour flat_fee hourly_breakfix }`
- `model Company { id String @id @default(cuid()) name String createdAt DateTime @default(now()) updatedAt DateTime @updatedAt sites Site[] contacts Contact[] contracts Contract[] assets Asset[] }`
- `model Site { id String @id @default(cuid()) companyId String company Company @relation(fields: [companyId], references: [id], onDelete: Cascade) addressLine1 String addressLine2 String? city String state String postalCode String country String isPrimary Boolean @default(false) contacts Contact[] assets Asset[] createdAt DateTime @default(now()) updatedAt DateTime @updatedAt }`
- `model Contact { id String @id @default(cuid()) companyId String company Company @relation(fields: [companyId], references: [id], onDelete: Cascade) siteId String? site Site? @relation(fields: [siteId], references: [id], onDelete: SetNull) name String email String? phone String? title String? createdAt DateTime @default(now()) updatedAt DateTime @updatedAt }`
- `model Contract { id String @id @default(cuid()) companyId String company Company @relation(fields: [companyId], references: [id], onDelete: Cascade) billingType BillingType blockHours Int? flatFeeAmount Decimal? @db.Decimal(10,2) hourlyRate Decimal? @db.Decimal(10,2) slaResponseMinutes Int? slaResolutionMinutes Int? startDate DateTime endDate DateTime? createdAt DateTime @default(now()) updatedAt DateTime @updatedAt }`
- `model Asset { id String @id @default(cuid()) companyId String company Company @relation(fields: [companyId], references: [id], onDelete: Cascade) siteId String? site Site? @relation(fields: [siteId], references: [id], onDelete: SetNull) name String assetType String serialNumber String? notes String? @db.Text createdAt DateTime @default(now()) updatedAt DateTime @updatedAt }`
- `src/lib/permissions.ts`: `Permission` union becomes `"dashboard:view" | "admin:manage_users" | "crm:view" | "crm:manage"`. `ROLE_PERMISSIONS` gains `"crm:view"` for all 5 roles (technician, dispatcher, sales, finance, admin) and `"crm:manage"` for `sales`, `finance`, `admin` ONLY (NOT technician, NOT dispatcher -- dispatcher needs read access to client context for ticket triage but does not own client/contract records per PROJECT.md's role descriptions). Also export `export const CRM_MANAGE_ROLES: Role[] = ["sales", "finance", "admin"];` as a named export alongside `Permission`/`ROLE_PERMISSIONS`/`can` -- this is the single source of truth later plans' Server Actions import for their `requireRole()` calls, instead of each plan hardcoding its own literal role array.
Edge/error cases:
- If `docker compose ps db` shows the `db` service is not running, start it with `docker compose up -d db` before running `prisma migrate dev` -- do not skip the migration or fake success.
- If `npx prisma migrate dev` fails because the database already has a conflicting migration state, read the error output fully and report the exact error in the result -- do not run `prisma migrate reset` (destructive) without explicit escalation.
- Cascade behavior: `Company` deletion cascades to all 4 child models (`onDelete: Cascade`). `Site` deletion on `Contact`/`Asset` uses `onDelete: SetNull` (a Contact/Asset should survive its Site being deleted, just lose the site association) -- do not use `Cascade` for the Site relation on Contact/Asset.
- `Contract` fields `blockHours`, `flatFeeAmount`, `hourlyRate` are all nullable by design (a `flat_fee` contract only populates `flatFeeAmount`, leaving the others null) -- do not add `@default` values or make them required.
