- `src/lib/validations/site.ts`: `export const siteSchema = z.object({ addressLine1: z.string().min(1), addressLine2: z.string().optional(), city: z.string().min(1), state: z.string().min(1), postalCode: z.string().min(1), country: z.string().min(1), isPrimary: z.boolean().default(false) })`
- `src/lib/actions/companies.ts`: `"use server"` module exporting `createCompany(formData: FormData)` and `updateCompany(id: string, formData: FormData)`. Both import `CRM_MANAGE_ROLES` from `@/lib/permissions` and call `await requireRole(CRM_MANAGE_ROLES)` before any database write (technician and dispatcher excluded -- CRM_MANAGE_ROLES is `["sales", "finance", "admin"]` per 02-01). Validate input with `companySchema`. On success, `redirect` to the company's detail page (create) or return `{ success: true }` (update). On validation failure, return `{ error: string }`.
- `src/lib/actions/sites.ts`: `"use server"` module exporting `createSite(companyId: string, formData: FormData)`, `updateSite(id: string, formData: FormData)`, `deleteSite(id: string)`. Same `requireRole(CRM_MANAGE_ROLES)` gate as companies.ts. Use `siteSchema` for validation.
- `src/app/(dashboard)/clients/page.tsx`: async Server Component. Calls `getCurrentUser()` from `@/lib/session`; if absent, redirect to `/login` (defense in depth, matching the dashboard layout's own pattern); if `!can(user.role, "crm:view")`, redirect to `/unauthorized`. Fetches all companies via `db.company.findMany({ orderBy: { name: "asc" } })`. Renders a `table` (shadcn) with Name column and a link to each company's detail page. Shows an "Add Company" button linking to `/clients/new`, but only rendered when `can(user.role, "crm:manage")` is true.
- `src/app/(dashboard)/clients/new/page.tsx`: Server Component wrapper that imports `CRM_MANAGE_ROLES` from `@/lib/permissions` and calls `await requireRole(CRM_MANAGE_ROLES)` (technician and dispatcher redirected to `/unauthorized`), rendering `CompanyForm` (a `"use client"` component in `src/components/crm/company-form.tsx`) which calls `createCompany` on submit.
- `src/app/(dashboard)/clients/[companyId]/page.tsx`: async Server Component. Uses the same `getCurrentUser()` + `can(user.role, "crm:view")` view-gate pattern as `/clients/page.tsx` above (not a hardcoded role array). Fetches the company by `params.companyId` via `db.company.findUnique({ where: { id: companyId }, include: { sites: true } })`; if not found, call Next.js `notFound()`. Renders a shadcn `Tabs` component with 4 `TabsTrigger`/`TabsContent` pairs: "Sites" (renders `SitesTab`, imported from `src/components/crm/sites-tab.tsx`), "Contacts" (renders `ContactsTab` from `src/components/crm/contacts-tab.tsx`), "Contracts" (renders `ContractsTab` from `src/components/crm/contracts-tab.tsx`), "Assets" (renders `AssetsTab` from `src/components/crm/assets-tab.tsx`). Pass `companyId={company.id}` as the only prop to each of the 4 tab components -- no plan may add a second prop without editing this file, which is outside every other plan's scope.
- `src/components/crm/tab-types.ts`: `export type CrmTabProps = { companyId: string };` -- exactly this one type, nothing else. This is the shared, compiler-checked contract every tab component (`SitesTab` and the 3 Wave 3 replacements) imports and uses as its prop type, replacing prose-only signature matching.
- `src/components/crm/sites-tab.tsx`: `"use client"` (or Server Component wrapper + client form, implementer's choice) component `export function SitesTab(props: CrmTabProps)` (importing `CrmTabProps` from `./tab-types`) that lists the company's sites in a table and includes a `SiteForm` to add a new one, calling `createSite`.
- `src/components/crm/contacts-tab.tsx`, `contracts-tab.tsx`, `assets-tab.tsx`: EXACT placeholder stubs, each importing `CrmTabProps` from `./tab-types` and declared as a **synchronous, non-`async`** function component: `import type { CrmTabProps } from "./tab-types"; export function ContactsTab(props: CrmTabProps) { return <p className="text-sm text-muted-foreground">Contacts coming soon.</p>; }` (same pattern for `ContractsTab`/"Contracts coming soon." and `AssetsTab`/"Assets coming soon."). Synchronous is required so Wave 3 plans replacing a stub with an `async` Server Component is a valid, anticipated signature evolution. These are intentionally minimal -- Wave 3 plans will overwrite the file bodies but must preserve the exported function name and the `CrmTabProps` prop type (by importing it from `./tab-types`, not re-declaring it inline).
Edge/error cases:
- A company with zero sites: `/clients/[companyId]` must still render without erroring; the Sites tab shows an empty state (e.g. "No sites yet").
- Invalid `companyId` in the URL: `notFound()` must be called, not an unhandled exception.
- A technician navigating directly to `/clients/new` by URL: must be redirected to `/unauthorized` by `requireRole`, not merely hidden in the UI.
- Duplicate site `isPrimary: true` on the same company: allowed at the schema level (no unique constraint per 02-01) -- do not add extra validation logic to prevent this in this plan; it's out of scope.
