Required interfaces/content structure:
- `src/lib/validations/contract.ts`: a zod discriminated union on `billingType`:
  ```
  const baseFields = { startDate: z.coerce.date(), endDate: z.coerce.date().optional(), slaResponseMinutes: z.coerce.number().int().positive().optional(), slaResolutionMinutes: z.coerce.number().int().positive().optional() };
  export const contractSchema = z.discriminatedUnion("billingType", [
    z.object({ billingType: z.literal("block_hour"), blockHours: z.coerce.number().int().positive(), ...baseFields }),
    z.object({ billingType: z.literal("flat_fee"), flatFeeAmount: z.coerce.number().positive(), ...baseFields }),
    z.object({ billingType: z.literal("hourly_breakfix"), hourlyRate: z.coerce.number().positive(), ...baseFields }),
  ]);
  ```
  (Exact field names/types must match; the discriminated union is what enforces "the correct fields for that type only" from this plan's must_haves.)
- `src/lib/actions/contracts.ts`: `"use server"` exporting `createContract(companyId: string, formData: FormData)`, `updateContract(id: string, formData: FormData)`, `deleteContract(id: string)`. Each imports `CRM_MANAGE_ROLES` from `@/lib/permissions` and calls `await requireRole(CRM_MANAGE_ROLES)` first -- do not hardcode a literal role array. Parse `formData` into a plain object, run `contractSchema.safeParse`, return `{ error: string }` (concatenate zod issue messages) on failure. On success, `db.contract.create`/`update` with only the fields relevant to the parsed billing type (other billing-type-specific columns stay `null`/`undefined`). Catch `P2025` in update/delete, return `{ error: "Contract not found" }`.
- `src/components/crm/contracts-tab.tsx`: preserve `export function ContractsTab(props: CrmTabProps)`, importing `CrmTabProps` from `./tab-types`. List the company's contracts showing billing type, the relevant amount/rate field for that type, SLA targets, and start/end dates. Render `ContractForm` below.
- `src/components/crm/contract-form.tsx`: `"use client"` component. A `select` (shadcn) for `billingType` (3 options: Block Hours, Flat Fee, Hourly Break-Fix); conditionally render the one relevant amount/rate input based on the selected billing type (client-side conditional rendering, not all 3 fields shown at once); date inputs for `startDate`/`endDate`; number inputs for SLA response/resolution minutes. Calls `createContract(companyId, formData)` on submit.
Edge/error cases:
- Switching billing type in the form before submit must clear/hide the previous type's now-irrelevant field so a stale value isn't submitted for the wrong type.
- `endDate` before `startDate`: not required to validate in this plan (out of scope -- note as an accepted gap, do not add extra validation not specified here).
- A contract with no SLA fields set (both optional): must be allowed -- SLA targets are optional per the schema.
- Deleting/updating a nonexistent contract: caught via `P2025`, returns `{ error: "Contract not found" }`, no unhandled exception.
