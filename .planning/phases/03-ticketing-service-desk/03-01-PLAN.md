Evaluate in this exact order and return on the first match: (1) if `slaResolutionDeadline` is null, return `"no_sla"`; (2) if `resolvedAt` is set (ticket is resolved/closed), return `"met"` if `resolvedAt.getTime() <= slaResolutionDeadline.getTime()` else `"breached"`; (3) if not yet resolved and `(now ?? new Date()).getTime() >= slaResolutionDeadline.getTime()`, return `"breached"`; (4) if not yet resolved and `(now ?? new Date()).getTime() >= slaResolutionDeadline.getTime() - 60 * 60 * 1000` (i.e. 1 hour or less remains before the deadline, a fixed absolute threshold regardless of the ticket's total SLA window length -- a ticket whose full resolution window is itself under 1 hour, e.g. an urgent-priority contract, is therefore "approaching" from the moment it is created; this is accepted as correct, not a bug, since such tickets genuinely have very little slack), return `"approaching"`; (5) otherwise return `"on_track"`. Use exactly this fixed 1-hour-remaining rule -- do not implement a percentage-of-window calculation; this function intentionally does not receive `createdAt` and a percentage-based threshold is not computable from its inputs.
