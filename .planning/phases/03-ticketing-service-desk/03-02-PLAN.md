Required interfaces/content structure:
- `src/lib/validations/ticket.ts`: zod schema(s) validating `companyId` (required string), `contactId`/`assetId`/`assignedToId`/`contractId` (optional, `"none"` sentinel accepted and stripped before reaching the Server Action per the established Contact/Asset form pattern), `status` (enum), `priority` (enum), `subject` (required, non-empty string), `description` (required, non-empty string).
- `src/lib/actions/tickets.ts`: `"use server"` at top. `createTicket(formData: FormData)` -- `await requireRole(TICKET_MANAGE_ROLES)` as literal first line, validates via zod, resolves the company's active Contract using the exact "Active-contract resolution rule" locked in `.planning/phases/03-ticketing-service-desk/03-CONTEXT.md` (among the company's contracts where `endDate IS NULL OR endDate >= now()`, order by `startDate DESC, id DESC`, take the first row; `null` if none match) if not explicitly provided -- this rule is shared verbatim with Plan 03-03's poller and must not be reworded or reimplemented differently, calls `computeSlaDeadlines(contract, new Date())` from `@/lib/sla`, creates the Ticket with `source: "manual"`, `contractId` snapshotted, and the computed deadline fields, then `redirect()`s to the new ticket's detail page. `updateTicket(id: string, formData: FormData)` -- same role gate, updates subject/description/priority/company/contact/asset (NOT status or assignedToId -- those are separate actions), P2025-handled, `revalidatePath`. `updateTicketStatus(id: string, status: TicketStatus)` -- same role gate (TICKET_MANAGE_ROLES), updates `status`, sets `resolvedAt = new Date()` when transitioning to `"resolved"` or `"closed"` (and clears it back to `null` if transitioning away from those states back to an open state), P2025-handled, `revalidatePath`. `assignTicket(id: string, assignedToId: string | null)` -- `await requireRole(TICKET_ASSIGN_ROLES)` as literal first line (NOT TICKET_MANAGE_ROLES -- assignment is dispatcher/admin only per 03-CONTEXT.md), updates `assignedToId`, P2025-handled, `revalidatePath`. `deleteTicket(id: string)` -- `await requireRole(TICKET_MANAGE_ROLES)`, deletes (cascades to TicketComment per schema), P2025-handled, `redirect()` to `/tickets`.
- `src/lib/actions/ticket-comments.ts`: `"use server"`. `addComment(ticketId: string, formData: FormData)` -- `await requireRole(TICKET_MANAGE_ROLES)` (commenting is part of working a ticket, same role set as manage), creates a `TicketComment` with `authorId` from `getCurrentUser()`, `isInternal` from form input, `revalidatePath`.
- `src/components/tickets/sla-badge.tsx`: `"use client"` or server-renderable (implementer's choice, but must not require client-only state) component `SlaBadge({ ticket }: { ticket: { status: string; slaResponseDeadline: Date | null; slaResolutionDeadline: Date | null; firstRespondedAt: Date | null; resolvedAt: Date | null } })` that calls `getSlaStatus(ticket)` and renders a shadcn `Badge` with distinct visual variants for `"no_sla"` (muted/outline), `"on_track"` (default/green-ish), `"approaching"` (warning/yellow), `"breached"` (destructive/red), `"met"` (default/green). Used identically in `ticket-card.tsx` and the detail page.
- `src/components/tickets/kanban-board.tsx`: `"use client"`, wraps a `DndContext` from `@dnd-kit/core` around one `KanbanColumn` per `TicketStatus` value (in the fixed order `new, in_progress, waiting_on_client, resolved, closed`), handles `onDragEnd` by calling `updateTicketStatus(ticketId, newStatus)` from `@/lib/actions/tickets` when a card is dropped on a different column, and only renders drag handles / allows drops for users where `can(role, "ticket:manage")` is true (read-only view for roles without manage permission, e.g. sales/finance retain `ticket:view` but cannot drag).
- `src/components/tickets/kanban-column.tsx`: receives a status label and its filtered ticket list, renders a `SortableContext` of `TicketCard`s.
- `src/components/tickets/ticket-card.tsx`: renders subject, priority badge, assignee avatar/name (or "Unassigned"), and `SlaBadge`; links to the detail page.
- `src/components/tickets/ticket-form.tsx`: `"use client"`, per-field `useState` + manually-built `FormData` passed to `createTicket`/`updateTicket`, following `company-form.tsx`'s exact pattern including `isNextRedirectError` in the catch block. Company select is required; contact/asset/assignee selects use the `"none"` sentinel pattern from `contact-form.tsx`/`asset-form.tsx` for optional relations, filtered to the selected company where applicable (contact/asset lists scoped to the chosen company, assignee list is all users).
- `src/components/tickets/ticket-comment-form.tsx`: `"use client"`, textarea + internal-note checkbox, calls `addComment`.
- `src/app/(dashboard)/tickets/page.tsx`: async Server Component, `await requireRole` is NOT used here (view-only should reach roles with only `ticket:view`) -- instead gate with `const user = await getCurrentUser(); if (!user || !can(user.role, "ticket:view")) redirect("/unauthorized")`, self-fetches all tickets via `db.ticket.findMany` with needed relations (`assignedTo`, `company`), renders `<KanbanBoard tickets={...} currentUserRole={user.role} />`.
- `src/app/(dashboard)/tickets/new/page.tsx`: same `ticket:view`-or-stricter gate pattern but requiring `ticket:manage` since this is a create action entry point -- gate with `can(user.role, "ticket:manage")`, self-fetches company/contact/asset/user lists for the form's selects, renders `<TicketForm ... />`.
- `src/app/(dashboard)/tickets/[ticketId]/page.tsx`: gate with `ticket:view`, self-fetches the ticket with all relations plus its comments (ordered `createdAt asc`), renders ticket details, `SlaBadge`, comment list (respecting `isInternal` visibility -- for this phase, since there is no external portal, all authenticated `ticket:view` users may see internal comments; do not add customer-facing filtering, that is out of scope per PROJECT.md's deferred self-service portal), `TicketCommentForm` (gated to `ticket:manage` users only for adding comments), and an assignment control (gated to `ticket:assign` users only, calling `assignTicket`).
- `src/components/nav/app-sidebar.tsx`: add a Tickets nav item following the exact same pattern as the existing Clients item -- `{can(role, "ticket:view") && <Link href="/tickets">...</Link>}`.
