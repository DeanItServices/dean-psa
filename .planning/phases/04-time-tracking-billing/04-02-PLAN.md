Required interfaces/content structure:
- `src/lib/billing.ts`:
  - `export type ContractBillingInput = { billingType: "block_hour" | "flat_fee" | "hourly_breakfix"; blockHours: number | null; flatFeeAmount: number | string | null; hourlyRate: number | string | null };` (use `number | string` for Decimal-derived fields since Prisma's `Decimal` serializes to a `Decimal.js`-like object at runtime, not a plain `number` -- the caller is responsible for converting to a plain number or numeric string before calling; document this expectation in a comment).
  - `export type BillingChargeResult = { quantity: number; unitRate: number; amount: number; description: string };` -- represents one resulting line item's worth of charge (quantity in hours, unitRate in dollars/hour or a flat amount, amount = quantity * unitRate, description a human-readable label e.g. "Block-hour overage" or "Flat-fee managed services").
  - `export function computeBlockHourCharge(contract: ContractBillingInput, currentPeriodBillableMinutes: number, priorInvoicedBillableMinutes: number): BillingChargeResult` -- computes cumulative total minutes as `priorInvoicedBillableMinutes + currentPeriodBillableMinutes`, converts `blockHours` to minutes (`blockHours * 60`), and if cumulative total exceeds the block-hours-in-minutes, bills only the overage portion that falls within the CURRENT period (i.e. `overageMinutes = min(currentPeriodBillableMinutes, max(0, cumulativeTotalMinutes - blockMinutes))`) at `hourlyRate` per hour (`overageMinutes / 60 * hourlyRate`). If `blockHours` or `hourlyRate` is null, treat overage as unbillable (return a zero-amount result) rather than throwing -- an incompletely configured contract should not crash invoice generation. Returns `{ quantity: overageMinutes / 60, unitRate: hourlyRate ?? 0, amount: computed, description: "Block-hour overage" }`.
  - `export function computeFlatFeeCharge(contract: ContractBillingInput): BillingChargeResult` -- always returns `{ quantity: 1, unitRate: flatFeeAmount ?? 0, amount: flatFeeAmount ?? 0, description: "Flat-fee managed services" }` regardless of any hours argument (flat-fee takes no time-based input at all -- do not add a minutes parameter to this function's signature).
  - `export function computeHourlyBreakfixCharge(contract: ContractBillingInput, currentPeriodBillableMinutes: number): BillingChargeResult` -- returns `{ quantity: currentPeriodBillableMinutes / 60, unitRate: hourlyRate ?? 0, amount: (currentPeriodBillableMinutes / 60) * (hourlyRate ?? 0), description: "Hourly break-fix" }`.
  - `export function computeContractCharges(contract: ContractBillingInput, currentPeriodBillableMinutes: number, priorInvoicedBillableMinutes: number): BillingChargeResult` -- dispatches on `contract.billingType` to the 3 functions above, passing only the arguments each specific function needs (flat-fee ignores both minute arguments; hourly-breakfix ignores `priorInvoicedBillableMinutes`; block-hour uses both). This is the sole function Plan 04-05 imports and calls -- the other 3 exported functions exist for direct unit-level testability but are not required to be called individually by any other plan.
- `src/lib/timer.ts`:
  - `export function computeElapsedMinutes(startedAt: Date, endedAt: Date | null, now?: Date): number` -- returns whole minutes elapsed between `startedAt` and (`endedAt` if set, else `now ?? new Date()`), rounded down (`Math.floor`), never negative (clamp to 0 if `endedAt`/`now` is somehow before `startedAt`).
  - `export function formatDuration(minutes: number): string` -- formats a minute count as a human-readable `"Xh Ym"` string (e.g. `125` -> `"2h 5m"`, `45` -> `"0h 45m"`, `0` -> `"0h 0m"`). Must not throw on `0` or on very large values.
Edge/error cases:
- `computeBlockHourCharge` must not produce a negative `amount` -- if cumulative minutes are under the block allotment, overage is 0, not negative.
- `computeBlockHourCharge`/`computeHourlyBreakfixCharge` must treat a null `hourlyRate` as "unbillable" (amount 0), not throw or default to some other rate.
- `computeElapsedMinutes` must handle `endedAt: null` (running timer) by using `now` instead, and must handle a clock-skew case where `now`/`endedAt` is before `startedAt` by returning 0, not a negative number.
- None of the 6 exported functions may perform any I/O, throw on missing optional fields (nulls must be handled per the rules above), or mutate their input arguments.
