- `src/lib/actions/time-entries.ts`: `"use server"` at top. `export async function startTimer(ticketId: string)` -- calls `requireRole(TIME_ENTRY_MANAGE_ROLES)` first, then checks for an existing `TimeEntry` where `userId` = current user and `endedAt: null`; if found, return `{ error: "You already have a timer running. Stop it before starting a new one." }`. Otherwise, read the ticket's `contractId` (snapshot it onto the new entry, mirroring Ticket's own pattern) and create a `TimeEntry` with `startedAt: new Date()`, `endedAt: null`, `isBillable: true` (default), `contractId` snapshotted from the ticket. Catch a unique-constraint violation from the DB-level partial index (Prisma error code `P2002`) as a redundant backstop, returning the same friendly error. `revalidatePath` the ticket detail page. `export async function stopTimer(timeEntryId: string)` -- calls `requireRole(TIME_ENTRY_MANAGE_ROLES)` first, loads the entry, computes `durationMinutes` via `computeElapsedMinutes(entry.startedAt, new Date())` from `@/lib/timer`, updates `endedAt: new Date()` and `durationMinutes`. Handles P2025 (entry deleted concurrently) returning `{ error: "Time entry not found" }`. `export async function updateTimeEntry(id: string, formData: FormData)` -- validates via `timeEntryUpdateSchema.safeParse`, updates `isBillable`/`notes` only; must reject (return `{ error: "This time entry has already been invoiced and cannot be edited." }`) if the entry's `invoiceLineItemId` is non-null, checked before attempting the update. `export async function deleteTimeEntry(id: string)` -- same invoiced-entry guard as update, then deletes; handles P2025.
- `src/components/tickets/timer-control.tsx`: `"use client"`. Props: `{ ticketId: string; runningEntry: { id: string; startedAt: Date } | null }`. Renders a "Start Timer" button calling `startTimer(ticketId)` when `runningEntry` is null, or a live elapsed-time display (using `computeElapsedMinutes`/`formatDuration` from `@/lib/timer`, re-rendering on an interval, e.g. `setInterval` every 30-60 seconds calling a re-render, not every second -- avoid excessive re-renders) plus a "Stop Timer" button calling `stopTimer(runningEntry.id)` when a timer is running. Uses `useTransition` or equivalent to show a pending state during the Server Action call, matching this codebase's existing client-component conventions (check `src/components/tickets/ticket-form.tsx` for the established button/pending-state style).
- `src/components/tickets/time-entry-list.tsx`: renders a table (or list, following the ticket comment list's non-table pattern if more consistent -- implementer's choice, but if a table, empty-state rows MUST set `colSpan` matching the actual column count per the established convention) of a ticket's time entries: technician name, duration (via `formatDuration`), billable toggle (disabled/read-only if `invoiceLineItemId` is set), notes. Read-only for users without `timeentry:manage`.
Edge/error cases:
- `startTimer` must handle the case where the ticket has no `contractId` (contractId snapshots as `null` on the TimeEntry -- this is valid, not an error).
- `stopTimer` must handle being called on an already-stopped entry (return `{ error: "Timer is already stopped" }` rather than overwriting `endedAt`/`durationMinutes`).
- `updateTimeEntry`/`deleteTimeEntry` must both check `invoiceLineItemId` is null before proceeding -- this is the mandatory guard against mutating billed data.
- `TimerControl` must not allow double-submission (disable the button during the pending state).
- If two browser tabs race to start a timer, the DB-level partial unique index (from 04-01) is the correctness backstop -- `startTimer`'s own pre-check is a UX nicety, not the sole guard. Catch the `P2002` error and return the friendly message rather than letting the raw Prisma error surface.
