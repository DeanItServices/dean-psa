<objective>
Make the database, not the JWT, authoritative for authorization — so that deactivating a user or changing their role takes effect immediately instead of up to eight hours later.

Purpose: `getCurrentUser()` (`src/lib/session.ts:14`) is today `return (await auth())?.user ?? null` — zero database queries. The JWT carries `role`, so a role edit is exactly as stale as a deactivation. This is the single highest-leverage change in the phase: one ~15-line edit at the one choke point that all 25 importers and every `requireRole()` call already funnel through, and it delivers immediate deactivation, immediate role changes, and the first-login password gate together.
Output: Modified `src/lib/session.ts` (database fresh-check), `src/auth.ts` (`authorize()` refuses inactive users), `src/app/(dashboard)/layout.tsx` (mustChangePassword redirect).
</objective>

Edge/error cases:
- A user deleted between token issue and request: `findUnique` returns null, `getCurrentUser()` returns null, the caller redirects to `/login`. Do not throw.

Do not silently fall back to the JWT's role — that would restore the staleness bug precisely when the database is unavailable to contradict it.
