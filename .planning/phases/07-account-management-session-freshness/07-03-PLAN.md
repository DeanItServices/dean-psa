1. Read `src/lib/permissions.ts` in full. Add `export const ADMIN_MANAGE_ROLES: Role[] = ["admin"];` alongside the other `*_ROLES` constants, with a doc comment matching their style. Change nothing else in the file.

3. Read `src/lib/actions/companies.ts` in full to internalise the exact action shape used in this codebase.
4. Write `src/lib/actions/users.ts` with `"use server"` and these exports:
   - `createUser(formData: FormData)` — gate, parse, lowercase-normalize the email, generate a temp password using `crypto.randomBytes` (Node's crypto, not Math.random), hash it with bcrypt at the same cost factor the seed uses, create the user with `mustChangePassword: true` and `isActive: true`, and return `{ tempPassword }` on success. Handle the unique-email collision (Prisma P2002) as `{ error: "A user with that email already exists" }`.
   - `updateUserRole(id: string, formData: FormData)` — gate, parse, refuse if `id` is the caller's own id, refuse if this would remove the last active admin, then write.
   - `resetUserPassword(id: string)` — gate, generate and hash a new temp password, set `mustChangePassword: true`, return `{ tempPassword }`.
   - `deactivateUser(id: string)` — gate, refuse if `id` is the caller's own id, refuse if this would remove the last active admin, then set `isActive: false`.
   - `reactivateUser(id: string)` — gate, set `isActive: true`. No guard rail needed; reactivation cannot reduce admin count.
   Each action ends with `revalidatePath("/admin/users")`.
5. Implement the last-active-admin invariant inside a `db.$transaction`, counting `{ role: "admin", isActive: true }` excluding the target row and refusing when the count would reach zero.
6. Run `npx tsc --noEmit`.
Required interfaces/content structure:
- All five actions are `async`, take the arguments listed above, and return either a success object or `{ error: string }`.
- `createUser` and `resetUserPassword` return `{ tempPassword: string }` on success — the only place that value ever appears.
- `ADMIN_MANAGE_ROLES` is exported from `src/lib/permissions.ts`.
Edge/error cases:
- Target user id does not exist: return `{ error: "User not found" }`, do not throw a raw Prisma error.
- Email collides with an existing account, including one differing only by case: the lowercase normalization means this surfaces as P2002; map it to a clear message.
- Self-deactivation and self-demotion: refuse both with distinct, honest messages. `requireRole` has already resolved the caller, so compare against that id — do not trust an id passed in from the client.
- Last active admin: refuse with a message that says why, e.g. "At least one active admin must remain".
- Demoting an admin who is already inactive does not reduce the ACTIVE admin count — count only active admins, or the guard rail will refuse valid operations.
- bcrypt hashing is CPU-bound; awaiting it inside a transaction holds a connection longer than necessary. Hash before opening the transaction.
