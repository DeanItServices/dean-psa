<objective>
Put an admin-facing surface on the user lifecycle built in 07-03, hanging it off the sidebar seam that has been wired and unused since Phase 1.

Purpose: `admin:manage_users` has existed as a `Permission` since Phase 1 (`src/lib/permissions.ts:10`) and has gated the sidebar's Admin section since then (`src/components/nav/app-sidebar.tsx:74`) — but the only link beneath it is `/admin/quickbooks`. Both the authorization plumbing and the navigation slot already exist; this plan fills them.
Output: New `src/app/(dashboard)/admin/users/page.tsx`, new components under `src/components/admin/`, and one added link in `src/components/nav/app-sidebar.tsx`.
</objective>

Required interfaces/content structure:
- Route: `/admin/users`, server-gated on `ADMIN_MANAGE_ROLES`.
- The page is a Server Component; the create form and row actions are client components.
- Every mutation goes through a 07-03 Server Action.
Edge/error cases:
- A guard-rail refusal from 07-03 (self-deactivation, self-demotion, last active admin) returns `{ error }` — display it. A control that silently does nothing is worse than one that explains why it refused.
- The admin viewing the page is in the list. Their own row's deactivate and role controls will be refused server-side; disabling or visually marking them client-side is good UX, but the server refusal remains the actual guarantee and must not be removed.
- A long user list is not a concern at this project's stated scale (well under 25 users) — do not build pagination.
- The temp password block must survive a re-render of its own component but must not survive a navigation away from the page. Do not attempt to make it recoverable.
