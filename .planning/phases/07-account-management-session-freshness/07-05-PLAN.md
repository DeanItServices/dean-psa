<objective>
Provide the two ways a person first gets into this system: the forced password change after an admin hands them a temp password, and the bootstrap path to the very first admin on a fresh deployment.

Purpose: 07-02 added a redirect to `/change-password` but deliberately did not create the route. Separately, the only way to get a real admin account today is a `prisma/seed.ts` run with `ALLOW_SEED_IN_PRODUCTION=true` or a direct database insert — `DEPLOYMENT.md` documents that honestly, and this plan replaces it with something defensible.
Output: New `src/app/(auth)/change-password/` route and action, new `scripts/create-admin.ts`, a `bootstrap:admin` npm script, and an updated `DEPLOYMENT.md`.
</objective>

Forbidden actions:

- Do not modify `src/app/(dashboard)/layout.tsx` to special-case the route. The route-group placement is the mechanism; a layout exception would be a second, redundant mechanism that can drift.
- Do not require the user's current or temporary password to set a new one. They arrived here because an admin issued them a credential out-of-band; re-entering it proves nothing the session has not already proven.
- Do not log the new password, the temp password, or any hash.
- Do not import `src/lib/db.ts` into `scripts/create-admin.ts` if that module is Next-runtime-coupled — follow `prisma/seed.ts`, which constructs its own `PrismaClient` with `PrismaPg`. Check before importing.
- Do not make the bootstrap script silently update an existing account. An operator running it twice must be told the account exists, not have its password quietly reset.
- Do not remove the `ALLOW_SEED_IN_PRODUCTION` guard rail from `prisma/seed.ts` — that file is forbidden here, and the guard rail is still correct. This plan retires it as the *documented* account-creation path, nothing more.
- Do not self-defer planned work.

Required interfaces/content structure:
- Route `/change-password` at `src/app/(auth)/change-password/page.tsx`, reachable while authenticated, outside the `(dashboard)` gate.
- `changePasswordAction` returns `{ error: string | null }` in the shape `login/actions.ts` established.
- `npm run bootstrap:admin` runs `scripts/create-admin.ts`.
Edge/error cases:
- A user with no session reaching `/change-password` directly: the action refuses. The page should send them to `/login` rather than rendering a form that cannot succeed.
- New password equals the temp password: acceptable to allow, but stating a minimum length and rejecting empty input is required.
- Bootstrap run against a database that has not been migrated: the Prisma call fails on the missing `isActive` column. Catch it and print a message pointing at `npm run db:migrate:deploy`, rather than surfacing a raw Prisma error.
- Bootstrap run twice with the same email: refuse with a clear message and a non-zero exit code. Do not update.
- `package.json` is listed in `sequential_files` — if any other plan in this wave also edits it, take the write lock rather than merging concurrently.
- The seeded E2E fixture accounts have `mustChangePassword: false` from 07-01, so they must never be redirected here. If they are, the bug is in 07-01's seed or 07-02's gate, not in this plan.
